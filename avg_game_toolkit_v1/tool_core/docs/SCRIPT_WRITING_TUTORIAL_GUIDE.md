# 游戏剧本写作教程总结

本文总结本地图片教程：

```text
<WORKSPACE_ROOT>/tutorial/如何写好的剧本/
```

这不是逐字 OCR，而是把教程里的剧本方法整理成我们可复用 AVG / 互动视频游戏工具链的写作规范。它的核心价值是：在规划剧情、角色、美术和交互前，先确认故事的“核心立意”。

## 1. 剧本能力金字塔

教程把游戏剧本能力理解成一个自下而上的金字塔。越底层，越决定上层是否成立。

```text
叙事技艺
  伏笔与回收、氛围营造、节奏控制

视听写作
  视听语言节奏、环境叙事、ADV / NVL 模式

结构设计
  起承转合、三幕剧、线性叙事、选项逻辑、交叉线、个人线、结局设计

人物设计
  角色核心欲望、角色关系网、角色对白、性格缺陷、服装 / 外观表达

宏观设计
  故事核心立意、世界观设计、叙事视角、设定集
```

对我们的工具链来说，最重要的提醒是：不要先堆节点、分支、角色和素材。最底层必须先有故事立意，否则剧情会变成流水账，玩家不知道故事到底要表达什么。

## 2. 核心立意是什么

教程里的关键句是：

```text
立意是一个故事的灵魂。
没有它，再多的展开写着写着也就散了。
```

“立意”不是一句宏大口号，也不一定是正确答案。它更像是：

- 这个故事真正想探索的问题；
- 玩家通关后留下的情绪；
- 主角欲望和世界阻力碰撞后暴露出的意义；
- 玩家在选择中反复面对的价值判断；
- 创作者自己最想表达的隐秘欲望、遗憾或困惑。

如果没有立意，剧情常见问题会是：

- 每个人物像按任务表出场；
- 剧情只是在介绍设定；
- 分支只是换地点或换角色；
- 选择没有价值压力；
- 结局没有余味；
- 美术和视频不知道该强化哪种情绪。

这正是我们之前一些 demo 里出现“剧情很跳”的根源之一。

## 3. 方法一：提出核心问题

不要一开始就想一个宏大的主题，而是先提出一个你真正想探索的问题。

例如：

- 被压迫的人该如何争取权利和自由？
- 如果记忆会被改写，身份还真实吗？
- 如果爱一个人需要背叛另一个承诺，你会怎么选择？
- 如果真相会毁掉当下的幸福，还要不要追寻？

根据问题答案，立意可以分为两种：

- 单一答案式：通常有明确真结局，其他结局用来反衬真结局的正确性。
- 多种答案式：没有绝对真结局，每个结局都是不同价值选择的平等结果。

对互动叙事来说，必须在规划阶段确定是哪一种。否则分支设计会摇摆：一会儿像路线选择，一会儿像真结局校验。

## 4. 方法二：寻找情感描点

另一种方式是先问：

```text
玩家通关后，心里应该留下什么情绪？
```

不同情绪会导向不同立意：

- 治愈：无论生活多糟糕，微小的善意也值得珍惜。
- 遗憾：错过的时光无法倒流，所以当下必须被认真对待。
- 震撼 / 反转：眼见未必为实，真相往往被偏见遮盖。
- 孤独：人和人之间的连接短暂，但短暂并不代表无意义。
- 释然：不是所有错误都能弥补，但人可以停止伤害自己。

这对我们的 runtime 很重要：如果核心情绪是“遗憾”，UI、音乐、节奏、美术 prompt、结局呈现都应服务遗憾；如果核心情绪是“治愈”，分支和画面就不能一直像灾难片。

## 5. 方法三：利用冲突反推立意

故事的本质是冲突。可以用这个模板反推：

```text
主角渴望 X，但反派 / 环境 / 自身缺陷阻碍 Y。
主角如何行动、付出什么代价、最后得到或失去什么，体现故事立意。
```

例子：

```text
主角想成为人上人，但代价是必须出卖朋友。
```

如果他拒绝出卖朋友并成功，立意可能是：

```text
友情胜过名利。
```

如果他出卖朋友并成功，最后孤独死去，立意可能是：

```text
异化的社会体制会吞噬人性。
```

同一个冲突，不同结局会表达不同立意。所以 Planner 不能只写“角色 A 想做什么”，还要写“这条线通过角色的选择表达什么”。

## 6. 方法四：从爽点反推

教程提醒：不要抗拒自己的“低级趣味”或奇怪脑洞，立意往往藏在那里。

做法：

1. 列出最想在游戏里实现的 3 个核心元素。
2. 问自己：我为什么对这些元素感兴趣？
3. 从答案里提取更深的欲望、恐惧或价值判断。

例子：

- 我想画一个巨大的废墟都市。
- 我想写一个性格很恶劣但很迷人的主角。
- 我想做一个至少必须死一个人的结局。

这背后可能不是“废墟很酷”，而是：

- 对失落文明的迷恋；
- 对道德灰度人物的好奇；
- 对不可挽回代价的情绪需求。

对我们工具链来说，这应该进入 project intake：用户给的“想要元素”不应被直接当成剧情，而应被 Planner 提炼成核心立意候选。

## 7. 方法五：从游戏玩法反推

视觉小说和传统小说最大的区别是玩家要做选择。立意必须体现在选项里。

不同玩法可以反推不同立意：

- 解谜：探寻真相的代价是什么？
- 养成：时间积累会如何改变关系或自我？
- 轮回：命运是否能被打破？重复是否让人更自由，还是更绝望？
- 恋爱路线：爱是理解、占有、补偿、逃避，还是共同成长？
- 生存选择：活下去是否一定值得？代价由谁承担？

教程用《VA-11 Hall-A》作为例子：它没有惊天动地的剧情，只是让玩家作为调酒师为客人调酒、倾听闲聊。但它的立意可以是：

```text
在绝望的世界里，哪怕只是调一杯酒的短暂连接，也可以成为人们继续生活的动力。
```

这对我们很关键：玩法不是外挂系统。玩法本身应当表达立意。

## 8. 立意总结模板

教程给了一个非常适合工具固化的模板：

```text
这是一个关于【主角身份】的故事，
主角试图【核心目标】，
却面临【核心冲突】，
最终发现【核心立意】。
```

或者：

```text
这是一个关于【主角身份】的故事，
主角试图【核心目标】，
却面临【核心冲突】，
主角的结局体现了【核心立意】。
```

我们后续每个项目都应强制产出 `story_intention_statement`，并且所有 agent 都围绕它工作。

示例结构：

```json
{
  "story_intention_statement": {
    "protagonist_identity": "负责校园祭最终夜收尾的男生执行委员",
    "core_goal": "在第一束烟火前完成封锁、灯控和天台钥匙归还",
    "core_conflict": "三个女生分别代表未兑现的承诺、现实中的责任、以及异界契约的召唤，逼他不能再用拖延逃避选择",
    "core_intention": "成长不是找到一个不会伤人的答案，而是在承认代价后认真回应他人和自己"
  }
}
```

## 9. 立意不等于宏大或正确

教程最后强调：

```text
立意不必宏大，不必爆裂，甚至不必正确。
```

好的立意往往藏在：

- 最隐秘的渴望；
- 最遗憾的过去；
- 最打动人的瞬间；
- 最想重写一次的结局；
- 最想让玩家记住的情绪。

立意不是给故事套一个大道理，而是让创作者心跳加速、愿意为之创作的东西。

这也意味着：我们的 Planner 不能只问用户“剧情是什么”，还要问或推断：

- 你真正想保留的爽点是什么？
- 你希望玩家最后难过、释然、甜蜜、震撼，还是空落？
- 哪个选择最应该让玩家犹豫？
- 哪个结局最应该让玩家回想前面的所有选择？

## 10. 对我们工具链的改造要求

这份教程应该新增一个强制 gate：

```text
G1.5 Story Intention Gate
```

它应发生在：

```text
Project Intake
-> Coherence Plan
-> Story Intention Gate
-> Story Graph Plan
```

在 `story_graph_plan.json` 之前，Planner 必须确认：

- 核心问题；
- 核心情绪；
- 核心冲突；
- 核心爽点；
- 玩法如何表达立意；
- 单一答案式还是多种答案式；
- 真结局是否存在；
- 每个主要角色代表或挑战立意的哪一面。

如果这些没有确定，不应启动 writer 扩写节点。

## 11. Agent 分工影响

Planner 负责：

- 从用户输入中提炼核心立意；
- 判断是单一答案式还是多答案式；
- 定义真结局 / 多结局的价值关系；
- 把立意翻译成故事图和分支原则；
- 当剧情、美术、机制冲突时，用立意做最终裁决标准。

Story Graph Director 负责：

- 把立意拆成主线问题、路线问题、结局问题；
- 让每个分支都测试同一个核心问题的不同侧面；
- 避免“换角色但不换价值压力”的假路线。

Scene Dramaturgy Agent 负责：

- 保证每个场景都有与立意相关的局部冲突；
- 让角色出场不是介绍设定，而是在追求欲望、回避代价、施加压力。

Narrative Writer 负责：

- 不把立意直接喊出来；
- 用行动、对白、误解、沉默、道具、场景转折表现立意；
- 确保每个选项被点击后都有情绪或价值上的回声。

Mechanics Agent 负责：

- 把变量、flag、好感、route gate、成就设计成能表达立意的系统；
- 避免纯数值刷好感导致故事失焦。

Art / UI / Video Agent 负责：

- 让美术风格和画面关键词服务核心情绪；
- 为核心冲突设计视觉证据；
- 把关键 CG / 视频留给立意最强的场面。

Checker Agent 负责：

- 检查每条路线是否都服务核心立意；
- 检查结局是否回收核心问题；
- 检查选择是否有价值压力；
- 检查角色是否只是工具人出场；
- 检查玩家是否能在视觉、文字和交互中感到同一个故事方向。

## 12. QA 检查清单

在剧情进入正式写作前，检查：

- 是否能用一句模板说清故事立意？
- 核心问题是否真的值得玩家选择？
- 核心情绪是否明确？
- 主角目标和核心冲突是否足够具体？
- 反派 / 环境 / 角色关系是否真的阻碍主角？
- 每个主要角色是否都代表立意的不同侧面？
- 每个分支是否测试了同一个核心问题？
- 玩法是否在表达立意，而不是只承担跳转功能？
- 结局是否体现立意，而不是单纯奖惩玩家？
- 美术 / 音频 / 视频是否知道要强化哪种情绪？

## 13. 对当前校园三角恋 Case 的启发

如果继续做校园三角恋，不能只写“三个女生同时出现”。应先确定立意。

可选方向：

```text
这是一个关于【害怕回应他人期待的男生】的故事，
主角试图【把校园祭最终夜平安收尾，并拖过所有没回答的问题】，
却面临【青梅竹马的旧承诺、隔壁班女生的现实危机、异界从者的契约召唤同时逼近】，
最终发现【逃避选择并不会减少伤害，真正的温柔是承认代价后认真回应】。
```

这样三个女主就不只是“可攻略对象”：

- 青梅竹马代表过去未兑现的承诺；
- 傲娇女生代表现实当下的责任；
- 异界从者代表命运 / 非日常诱惑；
- 玩家选择的不是“喜欢谁”，而是“如何面对承诺、责任、诱惑与逃避”。

这会直接改善开场和节点写作：每个角色出场都应带着具体欲望和压力，而不是机械展示信息。
