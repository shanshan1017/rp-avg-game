# Departments And Game Completion Gap

This document summarizes the current production departments, their major asset responsibilities, and what is still missing before the tool can reliably produce a complete playable AVG / interactive-video game.

## Current Department Coverage

The tutorial mind map roughly describes these departments:

- 剧本与叙事设计
- 美术与视觉传达
- 游戏玩法与机制
- 音频工程
- 项目管理与发行
- 编程 / 引擎 / Runtime

The current tool now maps them as follows.

## 7. Audio Design

Agent:

- `audio_agent.md`

Primary artifacts:

- `audio_plan.json`
- audio cue table
- audio prompt/reference notes when approved

Major responsibilities:

- BGM direction;
- ambience;
- sound effects;
- silence policy;
- optional voice policy;
- voice-cloning eligibility and risk checks;
- audio-runtime mapping;
- audio fallback if muted.
- video-audio boundary: video scenes carry their own embedded audio through the video prompt and normally do not need separate runtime audio files.

Major audio assets:

- BGM loops;
- location ambience;
- UI SFX;
- prop SFX;
- choice callback SFX;
- ending/failure stingers;
- optional voice lines.

Standalone audio generation/provider status:

- MiniMax audio is now documented as the standalone audio provider.
- Supported standalone capabilities are `audio.tts`, `audio.voice_design`, and `audio.music_generation`.
- API keys must come from `MINIMAX_API_KEY`; do not store keys in repo files or game-facing manifests.
- Current configured generation stack is image, video, and MiniMax standalone audio.
- Video can still generate its own embedded audio when enabled; do not duplicate video-internal sound as standalone runtime audio unless there is a deliberate transition/loop/replay need.
- Voice cloning is not enabled by default and requires explicit consent, licensing, source ownership, and Planner approval. Text-described MiniMax voice design should be treated as original synthetic voice design, not real-person cloning.

Status:

- Newly added as a first-class department.
- Schema now supports `audio` discipline and `audio_assets` budget.
- Still needs concrete `audio_plan.schema.json` if we want strict validation.

## What We Still Need Before A Complete Game

1. Intake and story intention for the concrete game.
2. Real isolated multi-agent run using the V2 prompts.
3. Approved `coherence_plan.json` with `story_intention`.
4. Approved `story_graph_plan.json` with route/intention alignment.
5. Approved `scene_dramaturgy_plan.json`.
6. Character/world bible and mechanics plan.
7. Segmented script that can compile into `runtime_game_package.json`.
8. Audio plan and asset plan.
9. Text-only playable package and CLI/browser playtest.
10. Runtime package validator:
    - target ids exist;
    - endings reachable;
    - values/flags used;
    - assets referenced;
    - required assets present;
    - no signed URLs/secrets.
11. Fixed runtime loader polished enough for player testing.
12. Prompt pack QA.
13. Only then: paid image/video/audio generation.
14. Asset download, local manifest, and runtime assembly.
15. Final coherence audit and playtest.

## Current Bottom Line

The tool now has the right departmental shape and schema direction. It is ready to run a text-first, prompt-first production pass.

It is not yet a one-click finished-game factory because the missing pieces are mostly execution automation and validators, not conceptual structure.
